# DataForge capability map

DataForge is absorbed into SkillForge/Rigor instead of running as a parallel product or execution stack.

## Implemented in the canonical platform

- Data Engineering is a first-class catalog and learning-path track.
- Python, SQL, data modeling, data architecture, distributed systems, system design, company preparation, adaptive tutoring, mock assessment, readiness, and evidence are served by the shared SkillForge platform.
- Source-backed attachment content maps PySpark, Databricks, Snowflake, cloud data, orchestration, governance, system design, and data-architecture topics into the data-engineering track.
- Company preparation uses the same canonical problem and candidate-state records.
- Run/Submit stays fail-closed and uses the shared isolated execution plane.

## Current execution evidence

The checked-in execution-readiness report is the source of truth:

| Subject | Source-backed rows | Runnable |
| --- | ---: | ---: |
| Python Coding | 1,368 | 824 |
| SQL | 940 | 20 |
| PySpark | 19 | 0 |

The 19 PySpark records have source-backed reference code but no concrete source-grounded Spark fixtures. They remain hosted/reference practice and MUST NOT be represented as graded/runnable.

A PySpark runtime alone is not sufficient to certify those records. A question becomes runnable only after it has concrete public and hidden Spark fixtures, deterministic expected outputs, reference validation, and an isolated production runner.

## Product mapping

- **DataForge Python/SQL practice** → canonical SkillForge Question Bank + execution plane.
- **DataForge data-engineering scenarios** → Data Engineering track + system/design practice.
- **DataForge personalized preparation** → SkillForge evidence, mastery, readiness, recommendations, and Layrs tutor.
- **DataForge company preparation** → company interview readiness / KeetKote capability.
- **DataForge mocks** → canonical mock and timed-practice surfaces.
- **DataForge PySpark content** → retained and discoverable, but fail-closed until grounded executable fixtures exist.

No duplicate DataForge service, database, identity system, or code-execution stack should be introduced.
